Environment Variables

Control the behavior of the action using these environment variables. Set them in your repository's Settings > Secrets and variables > Actions > Variables.

Variable Type Default Description
CREATE_TEMPLATES Optional true Enable/disable issue template generation
CREATE_LABELS Optional true Enable/disable GitHub label creation
AUTO_LABEL_ISSUES Optional true Enable/disable automatic issue labeling
RATE_LIMIT_DELAY Optional 0.5 Delay between GitHub API calls (seconds)
MAX_RETRIES Optional 3 Maximum retry attempts for failed operations
DEBUG_MODE Optional false Enable debug logging for troubleshooting
LABEL_PREFIX Optional "" Prefix for all generated labels

Example Environment Configuration

# .github/workflows/auto-label-issues.yml env: CREATE_TEMPLATES: true CREATE_LABELS: true AUTO_LABEL_ISSUES: true RATE_LIMIT_DELAY: 1.0 MAX_RETRIES: 5 DEBUG_MODE: false LABEL_PREFIX: "PROJ-"

Configuration File (config.yml)

The main configuration file that defines all labels, detection rules, and template settings.

Basic Structure

# config.yml labels: story_points: "⏳ Story Points: 1": color: "6f42c1" description: "Estimated effort: 1-2 hours" story_points: 1 keywords: ["1 hour", "quick", "simple"] difficulty: "🌱 Difficulty: Simple": color: "0e8a16" description: "Basic tasks with minimal complexity" difficulty: "simple" keywords: ["simple", "basic", "trivial"] priority: "🚨 Priority: Critical": color: "e11d21" description: "Urgent tasks that must be handled immediately" priority: "critical" keywords: ["urgent", "critical", "emergency"] templates: feature_request: enabled: true sections: - name: "Feature Description" required: true type: "text" - name: "Story Points" required: true type: "radio" options: ["1", "2-3", "5", "8", "13", "20+"] detection_rules: custom_keywords: "🔒 Security": keywords: ["security", "vulnerability", "auth"] color: "d73a4a" description: "Security-related changes" conditional_labels: "🚨 Priority: Critical": conditions: - has_label: "🔒 Security" - keyword: "urgent" color: "e11d21"

Label Configuration

Property Type Required Description
color string Required 6-digit hex color code (e.g., "6f42c1")
description string Required Label description (max 100 characters)
keywords array Optional Keywords that trigger this label
story_points number Optional Numeric story point value
difficulty string Optional Difficulty level identifier
priority string Optional Priority level identifier

Workflow Triggers

Configure when the action should run using GitHub workflow triggers.

on:
  issues: [opened, edited, reopened, closed]
  pull_request: [opened, edited, synchronize, reopened, closed]
  repository_dispatch: [create_labels, cleanup, update]

Trigger Types

Issues

  • opened - When a new issue is created
  • edited - When an issue is modified
  • reopened - When a closed issue is reopened
  • closed - When an issue is closed

Pull Requests

  • opened - When a new PR is created
  • edited - When a PR is modified
  • synchronize - When new commits are pushed
  • reopened - When a closed PR is reopened
  • closed - When a PR is closed

Repository Dispatch

  • create_labels - Manually trigger label creation
  • cleanup - Clean up orphaned labels
  • update - Update existing labels

Manual Trigger Example

# Trigger label creation manually gh api repos/:owner/:repo/dispatches \ -f event_type=create_labels \ -f client_payload='{"action": "create_labels"}' # Trigger cleanup gh api repos/:owner/:repo/dispatches \ -f event_type=cleanup \ -f client_payload='{"action": "cleanup"}'

Label Detection Rules

The action uses multiple detection methods to automatically apply labels.

Detection Methods

1. Checkbox Detection

Detects checked checkboxes in issue templates:

# Detects: - [x] **Story Points: 5** if [[ "$issue_body" =~ "- \[x\] \*\*Story Points: 5\*\*" ]]; then labels_to_add+=("⏳ Story Points: 5") fi

2. Keyword Detection

Detects keywords in issue title and body:

# Detects: "Story Points: 5" or "story points: 5" if [[ "$combined_text" =~ [Ss]tory\s*[Pp]oints?\s*:\s*5 ]]; then labels_to_add+=("⏳ Story Points: 5") fi

3. File-based Detection

Detects labels based on changed files in pull requests:

# Detects JavaScript/TypeScript files if echo "$changed_files" | grep -q "\.js$\|\.jsx$\|\.ts$\|\.tsx$"; then labels_to_add+=("JavaScript") fi # Detects iOS-specific files if echo "$changed_files" | grep -q "ios\|iPhone\|iPad\|\.ipa$"; then labels_to_add+=("🍎 Platform-Specific: iOS") fi

4. Pattern Matching

Uses regex patterns for complex detection:

# Detects priority patterns if [[ "$combined_text" =~ [Pp]riority\s*:\s*[Cc]ritical ]]; then labels_to_add+=("🚨 Priority: Critical") fi # Detects difficulty patterns if [[ "$combined_text" =~ [Dd]ifficulty\s*:\s*[Hh]ard ]]; then labels_to_add+=("🔥 Difficulty: Hard") fi

Custom Detection Rules

Add your own detection rules for custom labels and workflows.

Custom Keywords

# config.yml detection_rules: custom_keywords: "🔒 Security": keywords: ["security", "vulnerability", "authentication", "authorization"] color: "d73a4a" description: "Security-related changes" "🚀 Performance": keywords: ["performance", "optimization", "speed", "latency", "slow"] color: "ff7800" description: "Performance improvements" "🎨 UI/UX": keywords: ["ui", "ux", "design", "interface", "user experience"] color: "ff6b6b" description: "User interface and experience changes"

Conditional Labels

# config.yml detection_rules: conditional_labels: "🚨 Priority: Critical": conditions: - has_label: "🔒 Security" - keyword: "urgent" - keyword: "emergency" color: "e11d21" description: "Critical security or emergency issues" "🔥 Difficulty: Hard": conditions: - has_label: "🚀 Performance" - story_points: ">= 8" color: "d73a4a" description: "Complex performance optimization"

Custom File Patterns

# config.yml detection_rules: file_patterns: "🔧 Configuration": patterns: ["*.config.*", "*.env*", "config/*"] color: "6f42c1" description: "Configuration file changes" "📊 Analytics": patterns: ["analytics/*", "tracking/*", "metrics/*"] color: "28a745" description: "Analytics and tracking changes"

Template Configuration

Customize issue templates to match your team's workflow.

Template Structure

# config.yml templates: feature_request: enabled: true title: "Feature Request" description: "Suggest a new feature for this project" sections: - name: "Feature Description" required: true type: "text" placeholder: "Describe the feature you'd like to see" - name: "User Story" required: false type: "text" placeholder: "As a [user type], I want [goal] so that [benefit]" - name: "Acceptance Criteria" required: true type: "checklist" items: - "Criterion 1" - "Criterion 2" - "Criterion 3" - name: "Story Points" required: true type: "radio" options: - "1" - "2-3" - "5" - "8" - "13" - "20+" - name: "Difficulty" required: true type: "radio" options: - "Simple" - "Easy" - "Moderate" - "Hard" - "Very Hard" - "Epic"

Section Types

Type Description Properties
text Single-line or multi-line text input placeholder, required, multiline
checklist List of checkboxes items, required
radio Single selection from options options, required
select Dropdown selection options, required, multiple
file File upload required, accept, max_size

GitHub API Endpoints

The action uses these GitHub API endpoints for various operations.

Label Management

GET /repos/:owner/:repo/labels → List all labels
POST /repos/:owner/:repo/labels → Create a new label
PATCH /repos/:owner/:repo/labels/:name → Update an existing label
DELETE /repos/:owner/:repo/labels/:name → Delete a label

Issue Management

GET /repos/:owner/:repo/issues/:issue_number → Get issue details
PATCH /repos/:owner/:repo/issues/:issue_number → Update issue (add labels)

Pull Request Management

GET /repos/:owner/:repo/pulls/:pull_number → Get PR details
PATCH /repos/:owner/:repo/pulls/:pull_number → Update PR (add labels)

Rate Limiting

GET /rate_limit → Check API rate limits

Error Handling

The action includes comprehensive error handling for various failure scenarios.

Common Error Types

Error Type HTTP Code Description Action
Rate Limit Exceeded 403 GitHub API rate limit reached Wait and retry with exponential backoff
Label Already Exists 422 Label with same name already exists Skip creation, continue with next label
Permission Denied 403 Insufficient permissions Log error, skip operation
Invalid Color 422 Invalid hex color format Use default color, log warning
Network Error Various Network connectivity issues Retry with exponential backoff

Retry Logic

# Retry function with exponential backoff retry_with_backoff() { local max_attempts=3 local attempt=1 local delay=1 local command="$@" while [ $attempt -le $max_attempts ]; do if eval "$command"; then return 0 else echo "❌ Attempt $attempt failed. Retrying in $delay seconds..." sleep $delay attempt=$((attempt + 1)) delay=$((delay * 2)) fi done echo "❌ All attempts failed for command: $command" return 1 }

Rate Limiting

GitHub API has rate limits that the action respects and handles gracefully.

Rate Limit Check

# Check rate limit before operations check_rate_limit() { local remaining remaining=$(gh api rate_limit --jq '.resources.core.remaining' 2>/dev/null || echo "5000") if [ "$remaining" -lt 50 ]; then echo "⚠️ Rate limit low ($remaining remaining). Waiting 60 seconds..." sleep 60 fi }

Rate Limit Configuration

Default Limits:
  • Authenticated requests: 5,000 per hour
  • Unauthenticated requests: 60 per hour
  • Search API: 30 requests per minute
⚠️ Rate Limit Tips:
  • Use RATE_LIMIT_DELAY to add delays between requests
  • Enable DEBUG_MODE to monitor rate limit usage
  • Use repository dispatch for bulk operations
  • Consider running during off-peak hours

Troubleshooting

Common issues and their solutions.

Debug Mode

Enable debug logging to troubleshoot issues:

# Set in repository variables DEBUG_MODE=true # Or in workflow env: DEBUG_MODE: true

Common Issues

Labels not created:
  • Check repository permissions (need admin access)
  • Verify GitHub token has correct scopes
  • Check workflow logs for error messages
  • Ensure config.yml is valid YAML
Rate limit errors:
  • Increase RATE_LIMIT_DELAY to 1.0 or higher
  • Reduce MAX_RETRIES to avoid excessive retries
  • Run during off-peak hours
  • Use repository dispatch for bulk operations
Templates not generated:
  • Check Node.js dependencies are installed
  • Verify generate:templates script exists
  • Check for YAML syntax errors in config
  • Review workflow logs for template generation errors
