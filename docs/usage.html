Getting Started

Once you have the action installed, it will automatically label issues and pull requests based on their content. Here's how to use it effectively:

🎯 Automatic Detection

The action automatically detects story points, difficulty, priority, and development areas from issue content.

📋 Template Support

Use our professional issue templates with checkboxes for precise labeling control.

🏷️ File-based Labeling

Pull requests are automatically labeled based on changed files and technologies used.

⚙️ Customizable

Fully customizable labels, colors, and detection rules to match your workflow.

Creating Issues with Automatic Labeling

Method 1: Using Issue Templates (Recommended)

Our issue templates provide a structured way to create issues with automatic labeling:

Feature Request Template Example

## Feature Description Add dark mode support to the mobile app ## Story Points - [ ] **Story Points: 1** - [x] **Story Points: 2-3** - [ ] **Story Points: 5** - [ ] **Story Points: 8** - [ ] **Story Points: 13** - [ ] **Story Points: 20+** ## Difficulty - [ ] **Difficulty: Simple** - [x] **Difficulty: Easy** - [ ] **Difficulty: Moderate** - [ ] **Difficulty: Hard** - [ ] **Difficulty: Very Hard** - [ ] **Difficulty: Epic** ## Priority - [ ] **Priority: Critical** - [x] **Priority: High** - [ ] **Priority: Medium** - [ ] **Priority: Low** ## Development Area - [x] **🎨 Client Side** - [ ] **🖥️ Backend** - [ ] **☁️ Cloud Infrastructure** - [ ] **⚙️ DevOps**
💡 Tip: Check the appropriate checkboxes in the template, and the action will automatically apply the corresponding labels when you submit the issue.

Method 2: Keyword Detection

If you don't use templates, the action will detect keywords in your issue title and body:

Keyword Examples

Title: "Add user authentication - Story Points: 5, Difficulty: Moderate" Body: "We need to implement user authentication for our mobile app. This involves both frontend and backend work. Priority: High"

This would automatically apply:

⏳ Story Points: 5 🛠️ Difficulty: Moderate 🚨 Priority: High 🎨 Client Side 🖥️ Backend

Available Labels

Story Points

Estimate the effort required for the task:

⏳ Story Points: 1 - 1-2 hours ⏳ Story Points: 2-3 - 2-4 hours ⏳ Story Points: 5 - 5-8 hours ⏳ Story Points: 8 - 10-16 hours ⏳ Story Points: 13 - 16+ hours ⏳ Story Points: 20+ - 40+ hours

Difficulty Levels

Indicate the complexity of the task:

🌱 Difficulty: Simple - Basic tasks 👍 Difficulty: Easy - Low complexity 🛠️ Difficulty: Moderate - Medium complexity 🔥 Difficulty: Hard - High complexity 🧠 Difficulty: Very Hard - Advanced tasks ⚫ Difficulty: Epic - Multi-phase projects

Priority Levels

Set the urgency of the task:

🚨 Priority: Critical - Must handle immediately 🚨 Priority: High - Requires timely attention 🚨 Priority: Medium - Important but not urgent 🚨 Priority: Low - Minimal impact

Development Areas

Specify which part of the system is affected:

🎨 Client Side - Frontend, UI/UX, components 🖥️ Backend - APIs, databases, server logic ☁️ Cloud Infrastructure - AWS, deployment, infrastructure ⚙️ DevOps - CI/CD, automation, monitoring 👩‍💻 Component/UI - Individual UI components 🧠 Logic/Functions - Business logic, functions

Testing Types

Indicate testing requirements:

🔬 Testing: Unit - Unit tests for components 🧩 Testing: Integration - Integration tests 🌐 Testing: End-to-End - Full application tests 🔬 QA/Automation - Quality assurance tasks

Platform Specific

For mobile development projects:

🍎 Platform-Specific: iOS - iPhone/iPad specific features 🤖 Platform-Specific: Android - Android specific features

Pull Request Labeling

Pull requests are automatically labeled based on the files that were changed:

File-based Detection Examples

  • src/components/Button.tsx → 🎨 Client Side
  • api/auth/controller.js → 🖥️ Backend
  • Dockerfile → ⚙️ DevOps
  • ios/AppDelegate.swift → 🍎 Platform-Specific: iOS
  • android/MainActivity.kt → 🤖 Platform-Specific: Android
  • tests/unit/Button.test.js → 🔬 Testing: Unit
💡 Tip: The action analyzes all changed files in a pull request and applies relevant labels automatically.

Best Practices

For Issue Creation

  • Use templates: Templates provide structure and ensure consistent labeling
  • Be specific: Include relevant keywords in titles and descriptions
  • Check boxes carefully: Only check the most appropriate options
  • Update existing issues: Edit issues to add missing information

For Pull Requests

  • Use descriptive titles: Include the type of change in the PR title
  • Update related issues: Link PRs to issues using "Fixes #123" or "Closes #123"
  • Include context: Add descriptions explaining the changes

For Team Workflow

  • Standardize labels: Agree on label meanings with your team
  • Review regularly: Periodically review and clean up labels
  • Use filters: Create saved filters for common label combinations
  • Monitor performance: Track how well the automatic labeling works

Advanced Features

Custom Label Detection

You can add custom detection rules in your config.yml:

# config.yml custom_detection: "🔒 Security": keywords: ["security", "vulnerability", "authentication", "authorization"] color: "d73a4a" description: "Security-related changes" "🚀 Performance": keywords: ["performance", "optimization", "speed", "latency"] color: "ff7800" description: "Performance improvements"

Conditional Labeling

Set up conditional logic for more complex labeling:

# Example: Only apply "Critical" priority to security issues conditional_labels: "🚨 Priority: Critical": conditions: - has_label: "🔒 Security" - keyword: "urgent" color: "e11d21"

Label Analytics

Use our analytics tools to understand your labeling patterns:

# Generate analytics report npm run analyze:labels # Export label data npm run export:labels --format=json npm run export:labels --format=csv

Troubleshooting

Common Issues

Labels not applied?
Check that the action is enabled and the workflow has the necessary permissions. Review the Actions tab for any error messages.
Wrong labels applied?
The action might be detecting keywords incorrectly. Review your issue content and consider using templates for more precise control.
Performance issues?
If you have many issues, consider increasing the RATE_LIMIT_DELAY to avoid hitting GitHub API limits.
